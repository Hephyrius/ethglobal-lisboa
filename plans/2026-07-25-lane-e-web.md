# Lane E — dApp · `/web`

**Owner:** Lane E instance · **Claimed:** 2026-07-25 · **Scope:** master build plan §10 Lane E MVP

> This is the judge-facing surface. Everything else in this repo is invisible at judging time except
> through this app. The agent's visible reasoning is the product, not a debug panel.

---

## 1. What this lane is actually for

A judge spends maybe four minutes with us. In those four minutes they need to believe one claim:
**an autonomous agent is curating this vault, and here is the evidence.** Not "here is a nice DeFi
UI." The evidence is a causal chain, and the app's job is to draw it end to end:

```
   data the agent consulted   →   what it concluded   →   what it did on-chain
   (with provenance:              (its reasoning,          (tx hashes, on a
    which source, when)            verbatim)                block explorer)
```

Every design decision below is subordinate to rendering that chain convincingly. `AllocationDecision.
facts_used` holding real `Fact.id`s is what makes it drawable at all — that invariant
(`packages/schema/README.md`) is the load-bearing part of the whole interface for this lane.

Two secondary things earn disproportionate credibility and are cheap, so they are MVP, not stretch:

- **Rendering what the agent *could not* see.** `MarketSnapshot.errors[]` shown next to the reasoning
  says "this system knows the limits of its own inputs." Hiding it would be the obvious choice and
  the wrong one.
- **Rendering rejected decisions.** `AgentAction.status: "rejected"` plus
  `model.validation_retries` is the only visible proof that Lane B's output validation is
  load-bearing. A feed that only shows successes looks like a feed that has nothing to validate.

## 2. Constraints this lane builds under

| Constraint | Consequence for the design |
|---|---|
| Lane B's API may be down at any moment (and is, at hour 1) | Every screen must render from golden fixtures with **zero** network. Non-negotiable — see §4. |
| The Graph disqualifies mocked data on the demo path | The fixture fallback must therefore be **loudly visible**, never silent. §4. |
| Lane A's ABIs do not exist yet | Depend on the **ERC-4626/ERC-20 standard subset**, which is not Lane A's invention, and read addresses from `deployments/base-fork.json`. §6. |
| `packages/schema` is frozen | Gaps get filed in `docs/active-work.md` (done: #4 CORS, #5 mandate retrieval) and worked around client-side, not patched. |
| uint256 crosses as a decimal string | **Never `Number()` a balance.** All formatting goes through one bigint-safe module. §7. |
| macOS handoff at 10:00 | No absolute paths, no PowerShell, no OS-specific anything. `pnpm install && pnpm dev` on a fresh clone. |

## 3. Routes

| Route | Purpose | MVP contents |
|---|---|---|
| `/` | Entry. Explains the thesis in one screen and lists known vaults. | Thesis strip, vault list (locally-created + `deployments/base-fork.json`), CTA to `/create`. |
| `/create` | Genesis: co-design a strategy in natural language. | Chat against `POST /genesis/chat`; live-updating **mandate preview** with the granted data sources shown prominently; deploy via `POST /genesis/finalize`; redirect to the new vault. |
| `/vault/[address]` | The vault, and the agent running it. | Vault header + TVL/share price, holdings, deposit/withdraw (wagmi), mandate viewer, **decision feed**, "run agent tick" button. |

Genesis is deliberately one page, not a wizard. The narrative beat is *conversation produces a
mandate* — showing the mandate assemble itself beside the chat is the whole point, and a multi-step
form destroys it.

## 4. The fixture fallback — the decision that makes this lane un-blockable

`apiFetch` tries the live route with a short timeout, validates the response with the zod mirror, and
on **any** failure (network, non-2xx, schema mismatch) falls back to the golden fixture. It returns
the data *and* the mode it came from:

```ts
type Sourced<T> = { data: T; mode: 'live' | 'fixture'; note?: string }
```

Every screen surfaces that mode in a persistent badge in the header.

This is doing two jobs at once, and the second matters more than the first:

1. Lane E is never blocked on Lane B. Cross-lane request #3 is a courtesy, not a dependency.
2. **It makes accidentally demoing mock data structurally impossible.** The one failure mode that
   actually loses the Graph prize is standing in front of a judge with fixtures on screen believing
   they are live. A silent fallback is a trap; a loud one is a safety rail. If the badge says
   FIXTURES during the demo, we have a bug to fix, and we can see it from across the room.

A schema mismatch falling back is deliberate too: it means Lane B drifting from the frozen interface
shows up as a visible badge plus a console-legible zod error, not as a white screen.

## 6. Chain integration without Lane A

- **ABIs:** `CuratedVault` is an OZ ERC-4626 (§10 Lane A), so `deposit/mint/withdraw/redeem/asset/
  totalAssets/convertToShares/convertToAssets/balanceOf/decimals` are standard. I declare that subset
  as viem `as const` ABIs. When Lane A publishes `contracts/out/**`, anything vault-specific is
  additive; nothing here has to be rewritten.
- **Addresses:** never hardcoded — read from `deployments/base-fork.json`, which Lane A's deploy
  script overwrites.
- **Wallet:** **injected connector only** (MetaMask/Rabby/Coinbase extension). This drops
  `NEXT_PUBLIC_WALLETCONNECT_ID` from the critical path entirely — one fewer credential to be
  missing at 03:00, and a hackathon demo is driven from a browser extension anyway. WalletConnect is
  an additive connector later if anyone wants a phone wallet on stage.
- **Chain:** Base (8453) by id, RPC from `NEXT_PUBLIC_RPC_URL` so the same build points at the anvil
  fork or real mainnet. Explorer links suppressed on the fork — a dead BaseScan link in front of a
  judge is worse than no link.

## 7. Invariants this lane must not break

1. **Never `Number()` a uint256 string.** `formatUnits` (bigint) only. A silently wrong TVL is the
   most embarrassing possible bug here.
2. **APY is a fraction** — `0.0432` renders as `4.32%`.
3. **Parse every API response with the zod mirror.** Unvalidated JSON never reaches a component.
4. **`facts_used` ids that don't resolve are rendered as unresolved,** not dropped. The schema says
   they're how we catch a model inventing numbers; hiding them would defeat that.
5. **Fixture mode is always visible.**

## 8. Risks

| Risk | Mitigation |
|---|---|
| Lane B never lands / lands late | Fixture fallback (§4). Ships a full demo either way. |
| Lane B drifts from the frozen shapes | zod parse at the boundary → visible badge + legible error, not a blank screen. |
| CORS blocks every call at demo time | Filed as request #4 now, not discovered at 09:00. |
| No mandate for a vault this browser didn't create | Filed as #5; client-side cache + badged fixture fallback meanwhile. |
| Wallet stack peer-dep churn eats an hour | Next 14 / React 18 — the combination wagmi v2 has been stable against for over a year. Modernity is worth less than a wallet that connects. |
| Fork txs look identical to mainnet txs to a judge | Chain-aware explorer links + an explicit network badge. |

## 9. Order of work

1. Scaffold + providers + design system primitives → `pnpm build` green early.
2. `lib/api` + `lib/format` + fixtures. **Everything renders from fixtures before any live call.**
3. Decision feed (the centerpiece) — built first among features, against the fixture.
4. Vault page: state, holdings, mandate viewer.
5. Genesis chat + mandate draft + deploy.
6. Deposit/withdraw with wagmi.
7. README + build-log entries. Continuous, not at the end.

## 11. What changed during implementation

Recorded here because the plan is a living document (Rule 2); the reasoning is in
[docs/build-log.md](../docs/build-log.md).

**The fallback ladder grew a third rung: agent API → chain → fixtures.** §4 assumed two states. But
Lane B's `/vault/{addr}/state` is itself only reading the ERC-4626 contract, so when that service is
down there is no reason to fall all the way to invented numbers. `chain` is a distinct `SourceMode`
with its own badge; folding it into `fixture` would understate the truth, folding it into `live`
would hide that the agent is unreachable.

**`GET /health` became load-bearing.** §4 only defended against an unreachable API. Lane B's health
endpoint exposed a failure the plan missed entirely: the API can be up, healthy, and answering every
route perfectly *while itself running in fixture mode*. Every response validates, every request
succeeds, and the badge sits on green over fixtures served from the far side of the wire. It is now
folded into the same aggregate.

**Share price is derived, not read.** §7 invariant 3 asserted `share_price` is 1e18-scaled, on the
strength of the golden fixture. That was wrong as a general rule — the deployed vault's
`convertToAssets(1 whole share)` returns a 6-decimal asset amount, and Lane A independently flagged
the fixture as 1e12 off its own totals. The schema declares no scale, so the dashboard now derives
the figure from `total_assets`/`total_supply` with share decimals read from the contract.

**The `wagmi` React package was dropped for `@wagmi/core` + viem.** §6 assumed `wagmi`. Its
connectors barrel breaks the webpack build on an optional Coinbase peer and drags in ~347 unused
packages. The React bindings are ~40 lines instead.

**Genesis reads the source registry rather than a hard-coded list** (Lane C's request #19), which is
what makes "granting a source is a mandate edit, not a code change" true on this side too.

**Dependency supply-chain policy** was added mid-build at the user's request: every package pinned
exactly and ≥180 days old, install scripts disabled, enforced by
`web/scripts/audit-dependency-age.mjs`.

## 12. Verification status — what is proven and what is not

**Verified.**
- `pnpm build` and `tsc --noEmit` clean.
- All three routes rendered in a real browser (headless Edge), not inferred from a passing build.
- Every read function in `lib/chain/abis.ts` exercised by `eth_call` against Lane A's **deployed
  vault** on the fork — `asset`, `decimals`, `totalAssets`, `totalSupply`, `symbol`,
  `convertToAssets`, `previewDeposit`. This is also what confirmed share decimals (18) differ from
  asset decimals (6).
- Live integration with Lane B: all five frozen routes plus `/health`, `/vault/{addr}/mandate` and
  `/genesis/sources`, with CORS working from the browser.
- The provenance badge correctly reports FIXTURES while the agent API is up but in fixture mode —
  tested by running exactly that configuration.
- Golden fixtures parse through the zod mirror at build time (the landing page is prerendered, so
  drift fails the build).

**Not verified — the one gap, stated plainly.**

**Deposit and withdraw have never been signed.** The read path is proven against the real contract
and the write path is built on the same ABI constants, but no transaction has been submitted from
this app. Doing so needs a browser wallet holding a funded key, which a headless environment cannot
provide, and the alternative — broadcasting from an unlocked anvil account — would mutate fork state
that other lanes are asserting against.

*How to close it in about two minutes:* run the fork, import anvil account #0 into MetaMask, add a
network on `http://localhost:8540` with chain id 8453, open
`/vault/0x0E2c0e50E67B96C9C401C94e111a3DBD00DEB5d1`, connect, and deposit 1 USDC. The panel does
approve-then-deposit and waits for each receipt. **This is the top item for whoever picks the lane
up at 10:00.**
